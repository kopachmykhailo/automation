## Крок 2. Аналіз локаторів

Приклади для поля імені користувача на сторінці Swag Labs:

| Спосіб | Локатор | Стійкість і що може його зламати |
| --- | --- | --- |
| За роллю | `page.getByRole('textbox', { name: 'Username' })` | Висока: спирається на роль і доступне ім’я. Зламається, якщо поле перестане мати роль текстового поля або його доступне ім’я зміниться. |
| За текстом-підказкою | `page.getByPlaceholder('Username')` | Середня: зрозумілий і простий локатор. Зламається при зміні, перекладі або видаленні підказки. |
| За тестовим атрибутом | `page.getByTestId('username')` | Висока технічна стійкість: не залежить від оформлення чи видимого тексту. Зламається, якщо `data-test="username"` буде видалено або перейменовано. |
| За CSS-селектором | `page.locator('#user-name')` | Низька/середня: залежить від внутрішнього `id` елемента. Зламається при зміні `id` або структури форми. |
| За XPath | `page.locator('//input[@id="user-name"]')` | Низька: залежить від тегу й атрибута у DOM. Зламається при зміні розмітки, тегу чи `id`. |

У конфігурації Playwright `testIdAttribute` встановлено в `data-test`, бо саме
цей атрибут використовує Swag Labs (а не стандартний `data-testid`).

## Запуск

Виконуйте команди з папки `lab4` (не з кореня репозиторію `lab1`):

```powershell
Set-Location .\lab4
npm install
npx playwright install chromium firefox
npm test
npm run test:variant8
npm run test:ui
```

## Файли

- `playwright.config.ts` — конфігурація Chromium і Firefox.
- `tests/data.ts` — облікові дані тестового користувача.
- `tests/login.spec.ts` — прикладні тестові сценарії входу.
- `tests/inventory.spec.ts` — прикладні сценарії каталогу.
- `tests/checkout-variant8.spec.ts` — індивідуальні тести варіанта 8.
